# 每日基金 TOP50 与持仓分析

独立于仓库现有 A 股日报的 Python 项目。**按近一年收益从完整有效基金池选取前 50 个基金份额**，然后列出经理、成立时间、披露资产规模、净值及多周期排名，抓取公开披露股票持仓并计算行业/概念暴露。

## 如何运行

```bash
# 仓库根目录，建议 Python 3.12 / Linux 或 WSL
python -m pip install -r fund_tracker/requirements.txt
python -m fund_tracker.main
# 按基金类别筛选；每种口径单独运行，输出会成为最新一份报告
python -m fund_tracker.main --category 股票型
# 港股/海外证券等可导入经人工核实的分类
python -m fund_tracker.main --overrides /path/to/reviewed-tags.json
```

工作流：`.github/workflows/fund-tracker.yml`，名称 **基金 TOP50 与持仓分析**。

- 每天北京时间 **07:35**（UTC 前一日 23:35）运行；GitHub 可能延迟或漏调度，不是严格实时服务。
- 首次把本模块推送到 `main` 会运行测试，并在通过后启动真实采集。
- 可在 Actions → 基金 TOP50 与持仓分析 → **Run workflow** 手动执行和选择基金类别。
- 默认分支上才有定时执行；未合并的分支/PR不会启动每日采集。
- 仓库 Actions 需要启用；报告回写需要 `contents: write` 且分支保护允许机器人提交。不满足时报告仍可从本次运行附件下载。
- 自动任务不使用 AI Key，不需要付费金融接口，不修改已有 A 股日报工作流；私有仓库 Actions 用量按 GitHub 账户套餐计算。

## 输出

每次成功取得排名后写入 `reports/funds/YYYY-MM-DD/`，并更新 `reports/funds/latest/`：

| 文件 | 内容 |
| --- | --- |
| `index.html` | 自包含中文报告：可搜索榜单、展开逐只基金持仓、查看行业与概念权重 |
| `top50.csv` | 经理、成立时间、披露资产规模/日期、净值，以及各周期收益和排名/样本数 |
| `funds.json` | 完整嵌套数据、质量状态、缺失字段、持仓、分类与来源标识 |
| `holdings.csv` | 股票代码/市场、名称、权重、报告期、持股数、市值、行业和概念 |
| `allocations.csv` | 各基金的行业/概念汇总，占基金净值百分比 |
| `sources.json` | 实际采用的接口/网站、抓取时间、缓存命中、原始文件 SHA-256 |
| `summary.md` | Actions 运行摘要 |

原始响应保存在 `artifacts/fund-tracker/YYYY-MM-DD/`，连同失败诊断上传到 Actions 附件（保留 14 天），**不把大量原始响应提交进 Git 历史**。

GitHub 文件页通常只展示 HTML 源码：下载本次运行附件并解压后，用浏览器打开 `index.html`。HTML 不依赖 CDN，可离线浏览。报告下载链接依赖同目录 CSV/JSON 文件。该仓库为私有；本项目不会擅自启用公开 Pages。

## 排名口径：避免看起来完整、实际上误导

1. **基金池**：AKShare `fund_open_fund_rank_em(symbol="全部")` 对应的东方财富开放式基金排名池；不是货币基金七日年化排名，也不承诺覆盖全部场内 ETF、私募、银行理财。可切换股票型/混合型/债券型/指数型/QDII/FOF。
2. **选取条件**：有有效近一年收益；源站净值日期不在未来且距采集日不超过 14 个自然日（可通过 `--max-nav-age` 调整）。先在完整有效池计算每种排名，再取近一年排名前 50；各周期分母分别为该周期有效数据的基金数。
3. **排名方法**：降序竞赛排名 `1,1,3`。边界并列时按基金代码确定性截取，默认正好 50 只；不额外扩为 51 只。A/C/E 等不同份额以基金代码分别保留，不用名称猜测合并。
4. **收益口径**：使用源站的近一年、半年、三个月、一个月、一周收益率；不拿未复权净值比值冒充包含分红的收益。缺失值不是零。
5. **上一交易日**：以经校验覆盖采集日期的大陆交易日历，取严格早于北京时间采集日的最后交易日。只有基金净值日期恰等于该日，才进入日收益排名。QDII/延迟披露基金不匹配时留空；仍保留其真实净值日期与最新日收益在 JSON。日历不可确认时留空，不把简单工作日推算当交易日历。
6. **净值排名**：按单位净值数值排序，**净值高不代表收益好**。基金类型、币种与净值日期可能不同，未另行做汇率换算或同类标准化；比较基金时优先选相同类别、币种和日期。不要把此全池榜单称为专业同类业绩排名。
7. **规模**：读取披露资产规模及其截止日期，保留原单位与原文；不把份额规模、成立募集份额或未知单位数值当人民币资产净值。规模并非每日更新。
8. **无法完整采集**：排名关键字段变更、分页重复/截断、有效基金不足时失败退出，保留上一份 `latest`；单只基金资料或持仓失败则保留基金行、显示缺失和 `partial`，不伪造成功。
9. **历史**：每天归档当次快照，不支持把当前榜单倒填到过去。周末仍采集，但报告明确显示原净值日期。原始全池数据在 Actions 附件中用于核验；不是现成回测引擎。

## 持仓与行业、概念：代码为主，AI为辅

**本版本用接口和确定性代码完成事实分类与权重计算，不依赖 AI。**

- 基金股票仓位通常是定期披露，不是实时数据。每只基金仅使用最新可识别报告期，绝不把不同季度拼在一起累计；尝试本年，无可用披露时再查上一年。
- 季报往往仅披露重仓股，半年报/年报可能更完整；公开接口也可能截断。即使请求更多条目，也不能承诺拿到全部实时持股。报告保留范围说明、报告年龄及可能截断标志。
- 每个行业权重 = 已取得且匹配该行业的股票占基金净值比例之和；同时报告已取得持仓权重和分类覆盖率。未取得部分可能是其他股票、债券、现金等，不猜其类别。
- 概念是一股多标签，例如一只股票可能同时属于 AI 与云计算；概念权重可重叠，不能相加当成 100% 资产配置。明显的交易/机构标签单独放在 `market_tags`，其余保持来源板块口径，不当成统一的官方主题标准。
- `00700`（港股）不等于 `000700`（A股）。不会把港股或美股代码随意补零后查询 A 股接口。暂未可靠覆盖的市场保留未分类，可用经审核的扩展映射补充。
- 分类标签是抓取时点的标签，持仓是历史报告期，不能拿二者做声称无前视偏差的回测。

**AI 适合做解释层**：在这些结构化结果之上概括主题、比较策略、解释集中度。AI 不适合凭股票名称猜行业/概念或填补经理、规模、日期和持仓。若以后接入模型，应只传必要公开数据，强制引用来源，输出单独的“AI解读”，不覆盖事实列。当前版本未自动调用任何模型。

### 经人工核实的扩展分类

`--overrides` 读取 JSON 对象，以 `市场:证券代码` 为键。每项需 `source_url`、`as_of`（ISO 日期，不晚于采集日），可带 `industry` 和字符串列表 `concepts`。来源和人工标签会与接口标签区分保存。不要提交个人账户资料、付费接口密钥或未经核实的 AI 猜测。
